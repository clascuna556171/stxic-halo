# Monetization and go-to-market hypotheses

This is a proposal, **not** a finalized pricing plan.

## Positioning
"Stay in flow. Halo keeps watch." A Windows companion for AI-assisted development, not another cluttered all-in-one utility.

## Recommended early business model
Free during closed beta. Consider **free core** (local CPU/RAM + one provider + alerts) and a **one-time paid Pro license** for advanced history, multi-agent evidence and custom rules. Alternatively keep open-core if community contributions become important. Don't lock basic privacy or security behind payment.

Validate willingness-to-pay interviews first; token usage visibility alone is easy for competitors to copy. Avoid plans that introduce constant cloud storage or mandatory subscriptions unless users explicitly need syncing.

## Launch assets
- 16/24/32/48/256 px recognizable mark.
- 3–5 accurate Windows screenshots with a visible demo badge where data is simulated.
- 20–45 second real product video; no vaporware examples.
- Website with clear feature availability table and privacy statement.
- Known limitations, changelog and issue tracker.
- Store listing copy in `docs/release/STORE_LISTING.md`.

## Launch channels
GitHub, Windows developer communities, relevant coding-assistant communities (follow each community's promotion rules), short product clips. Give away an early reliable MVP and ask for concrete bug reports.

## What to test in user interviews
1. Can users explain Halo's purpose from a 5-second screenshot?
2. Do they trust its status enough to avoid checking the agent terminal?
3. Which alerts feel helpful vs noisy?
4. How hard is provider connection setup?
5. Is a small floating UI better than a tray-only app for their workflow?
