# Competitive Landscape — Research Snapshot

**Date:** 2026-10-25. Public README claims can change. Verify product versions before marketing any comparison. No competitor code or proprietary screenshots are included in this ZIP.

| Product | GitHub / website | Relevant capabilities | STXIC implication |
|---|---|---|---|
| HeyyCzer Windows Dynamic Island | https://github.com/HeyyCzer/windows-dynamic-island | Claude status/permissions, tokens/plan usage, system monitoring, media and notifications | A generic notch plus resource widgets is already crowded; project GPL-3.0—do not copy code into MIT repository |
| PILLAR | https://github.com/warpirate/pillar-dynamic-island-for-windows | Tauri/React/Rust floating utility; media, CPU/RAM, battery and assistant | Shows feasibility of lightweight Windows island; project MIT but do not copy its specific artwork/brand |
| Agent Island | https://github.com/jibc45453jibc/agent-island | Windows agent monitoring and usage snapshots; current README admits limits | Focus on validated cross-agent data and experience quality; README currently says no OSS license selected |
| AgentPulse | https://yazelin.github.io/AgentPulse/ | Multi-provider floating assistant activity monitoring | Multi-agent alone is not a differentiator |
| Nook | https://nook.zubyr.dev/ | Claude session status and attention hooks | Need better outcomes-oriented narrative, not 'monitor agent' alone |
| Intel PresentMon | https://github.com/GameTechDev/PresentMon | Frame present events and performance measurement | Possible future FPS data plane, but commercial distribution and anti-cheat testing needed |
| LibreHardwareMonitor | https://github.com/LibreHardwareMonitor/LibreHardwareMonitor | Hardware sensors with some access constraints | Possible future temperature and utilization integration, license review required |

## Opportunities
1. **Evidence:** distinguish a stopped agent response from validated work, with Git and test provenance.
2. **Risk Radar:** use explainable early warnings for real conflicts/failures, not generic notifications.
3. **Truthful data:** ensure token, context and quota readings are never blended or invented.
4. **Calm UX:** Windows overlay polish with careful focus/monitor/fullscreen semantics.
5. **Privacy:** local-first architecture, integration permissions and easy rollback.

## Differentiation risk
Proof-of-Work and risk detection can also be built into editors or terminal tools. Validate demand with 5–10 developers before overinvesting, and never claim exclusive ownership of these ideas.
